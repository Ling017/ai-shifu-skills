# 个性化教学设计

从老师的经验中提炼教法，让不同学员得到合适的帮助。

`ai-shifu-personalization-designer` 帮助教师、教研人员和课程创作者，把平时“凭经验就知道怎么带”的判断整理成可复用的方法，再根据具体课程的目标和学员表现设计因材施教。

版本：3.0.1 · 结构化交接协议：3.0 · 默认中文或按用户要求的语言交流。

## 你可能遇到过这些问题

- 能讲清楚知识，却说不清自己为什么这样教、什么时候换一种带法。
- 有书稿、教案和答疑记录，希望从中提炼教学特点。
- 已经整理了教师画像，希望应用到另一门课，又不想机械套用。
- 想把自己的教学经验交给模型或其他老师使用，需要说清判断依据和反馈标准。

例如，同样是“学员说没有思路”，老师可能先让他找出材料里看得懂的一处，再决定补背景、给示范，还是追问判断依据。这份Skill关注这样的教学决策。

## 会得到什么

| 产物 | 包含什么 |
| --- | --- |
| 教师画像 | 教学重点、判断逻辑、解释、提问、帮助与反馈方式，以及适用范围 |
| 课程教学设计 | 面对哪些表现改变什么教法，学员仍要做什么，哪些标准不变 |
| 可交接说明 | 来源、已确认内容、待核对推断、信息用途和可观察的验收依据 |

没有指定课程时，只完成教师画像。普通访谈和总结默认用自然语言；需要结构化交接时，再按协议3.0生成。

## 开始使用

本目录是一个完整的Agent Skill，入口为[SKILL.md](SKILL.md)。

在支持Agent Skills的工具中，按该工具的安装方式加载整个目录，保留 `references/`、`assets/` 和 `agents/` 的相对位置。不同工具的安装目录与调用方式可能不同。

使用不支持Skill自动加载的普通模型时，可以提供入口文件，并按任务补充所引用的参考文件；只给一个Skill名称不会让普通模型自动获得这些文件。

### 从经验开始访谈

```text
用个性化教学设计 Skill，访谈我，提炼我的教学判断和方法。
先从真实教学经历开始，一次问一个问题。
目前不指定课程。
```

模型会围绕一个教学片段逐步追问：学员表现是什么、你怎样判断、具体怎样帮助，以及后来发生了什么。不会要求你先填完背景、水平、目标和喜好问卷。

### 从资料中提炼

```text
用个性化教学设计 Skill，从我提供的教案和答疑记录中提炼教学特点。
标明来源位置，区分明确表述、实际行为和你的归纳。
先给自然语言总结，供我核对。
```

优先提供1—3份能看见教学判断的资料，例如有学员回应的答疑、作业讲评、不同学员的教学版本或课后反思。只提供书稿或单向讲授材料也可以，结论会保留相应的证据边界。

视频、音频等材料能否直接读取取决于当前工具；已有转写或文字稿可直接使用。

### 把画像应用到具体课程

```text
用个性化教学设计 Skill，结合这份教师画像，为成人入门课设计因材施教。
目标是让学员区分事实与推断，并说明判断依据。
请说明不同学员表现对应的帮助、补答和退出方式。
只输出教学设计，新增应用保留为草案。
```

模型会选择适用的方法，不要求每一节课都使用画像中的全部特点。

在可以按名称调用Skill的环境中，也可用 `$ai-shifu-personalization-designer` 明确指定。

## 与课程制作怎样衔接

教师画像 → 具体课程教学设计 → 接收方选择实现方式。

这份Skill描述教学行为和信息用途，不依赖MarkdownFlow、某个课程平台或课程创建Skill，也不要求API密钥。

接收方可以是模型、真人教师或课程制作工具。接收方决定输入形式、记忆、提示词和交付方式；不支持某项教学行为时，应说明缺口和替代方式。

教师画像确认只确认该画像；具体课程应用单独核对。已提供的原话、事实和质量要求不能被静默改变。

## 当前验证范围

3.0.1已完成独立访谈、资料萃取和旧画像交接三个代表场景的独立模型验证，另做了格式、引用和结构检查。详见[验证说明](VALIDATION.md)。

这些检查支持已测路径的表现，尚未进行真实学习效果实验，也不能保证所有模型和输入都有相同表现。

使用资料时，请确保有权提供，并去掉不必要的学员身份信息。模型归纳需要老师核对；资料呈现一种做法，不自动证明这种做法的效果。
