# 销售诊断

当用户已回复但下一步不明确时使用。只诊断推进所需信息，不要像审问用户。

## 先挖需求

不要急着给用户建议、结论、案例链接或报价。先判断用户问题背后的真实顾虑：

- 问案例：可能是在判断行业适配、效果证明、同类客户、内部汇报依据。
- 问价格：可能是在判断预算门槛、采购路径、试错成本。
- 问能不能做：可能是在判断功能边界、准确性、安全性、是否需要定制。
- 问怎么操作：可能是在判断上手难度、时间成本、是否需要团队协助。

好的回复先要体现“我理解你为什么这么问”，再问 1 个关键问题定位场景，最后给一个低风险下一步。

## 七个购买判断因素

| 判断因素 | 要识别什么 | 可用问题 | 销售含义 |
|---|---|---|---|
| 动机 | Why now? pain or opportunity | 你这次最想先解决哪个问题？ | Strong pain means push experience fast |
| 决策角色 | 使用者、推荐者、购买者、执行者 | 这件事主要是你自己用，还是还需要给同事/上级看？ | 如果不是购买者，要准备可汇报证据 |
| 场景规模 | Course count, learner count, usage mode | 第一阶段准备做几门课、给多少人学习/使用？ | Drives package direction |
| 时间 | 试用截止时间、上线时间、采购时间 | 你希望什么时候看到第一版效果？ | 时间越近，跟进强度越高 |
| 替代方案 | 当前工具/流程 | 现在是用录播、文档、群答疑，还是通用 AI 在做？ | 使用前后对比 |
| 成功标准 | 什么能说服用户 | 如果试点成功，你最想看到什么结果？ | 决定证明点 |
| 风险顾虑 | 价格、效果、操作、安全、AI 准确性 | 你现在最担心的是操作、效果、价格，还是采购流程？ | 选择对应异议处理 |

## 购买成熟度

| 等级 | 信号 | 动作 |
|---|---|---|
| R0 未识别 | Only says “了解一下” | Ask identity + need + material |
| R1 有兴趣 | Has scenario but no material/action | Push smallest first-course experience |
| R2 有行动 | Registered/installed/generated | Push to publish learning URL |
| R3 有证据 | 已看案例/示例、理解价值，或已有学习地址 | 先做价值确认，再轻判断套餐；不要陷入无限打磨 |
| R4 采购中 | Asks contract/invoice/corporate payment/brand/domain | Procurement path, deadline, escalation if needed |
| R5 已成交 | Paid/opened | Customer success activation |

## 不要跳过

- If no real material: do not over-sell; help pick minimal material.
- 如果没有学习地址：除非用户坚持问价，否则不要深入讲套餐，先推动证明点。
- 如果没有外部学习者验证：购买前不要强迫用户邀请真实学习者；用客户案例和个性化学习示例课建立证据，再推动套餐决策。
- 如果用户过早问价：先用资格判断和套餐方向回答，再回到证明点。
- 如果用户已有产出但觉得不完美：不要持续要求其改课或做新课；说明第一版不完美正常，课程质量会随着 AI 理解、提示词能力、资料准备和使用时间提升。
- 如果用户已认可形式：不要只停留在“继续体验”；温和说明正式使用和付费后的好处，并询问其下一步用途和规模。

## 体验期判断

15 天体验期的销售目标不是把用户训练成专家，也不是要求做出完美课程，而是帮助用户确认三件事：

- 产品可以：AI 师傅能把内容变成可互动、可发布、可体验的课程。
- 用户可以：用户自己能完成从资料到学习地址的基础闭环。
- 方向成立：用户的内容适合继续做成交互课、体验课、系列课或培训课。

体验期可以给支持和建议，但不要让用户反复发现“自己还做不好”。当用户已经完成发布并认可形式时，应进入价值确认和套餐判断。
