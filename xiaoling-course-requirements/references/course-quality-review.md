# 课程测试方法与要求

## 先与老师确定测试方向

依入口的测试方向澄清规则执行。方向不明时，用日常语言给出下面的选择，等老师回答后进入对应部分；老师选择“全部”也可直接作为范围。可先读取版本与已有材料，等待期间不自行开展未选定的测试。示例问法：

> 这次你最想确认课程的哪一方面：教学目标与内容、教学设计与学习体验、互动与动态教学、内容与运行硬伤，还是跨节衔接与完整路径？可以只选一个，也可以组合。如果暂时没有重点，我可以先根据课程现状提出建议。

沿用已知信息，只补影响测试的关键缺口：目标学员、实际起点与必要前提；整课／章节／课节／具体路径范围；课程版本及入口；只检查给建议还是允许修改复测；学习记录、草稿同步与发布等操作边界。局部任务不自动扩成全课检查，不新增操作授权。

## 按所选方向测试

只读取并执行所选方向的检查项，以及下文公共执行与交付要求。相关目标不清且会改变判断时，先核对已有目标，仍缺失再向老师补问；不为单一方向测试重新设计全课。范围外明显硬伤记录并说明影响。遇到阻断时优先记录、定位并说明可继续的范围；只有已获修复授权时才修改，只检查任务不自动转为修复。

### 教学目标与内容

- 整体目标是否说明目标学员、具体场景、要解决的问题及核心收获，而非仅列能力；课节目标如何支撑整体目标，为什么学、学什么、学会什么是否清楚。
- 必要知识是否准确完整，解释、适用条件、边界和前置知识是否充分；事实、来源及案例计算／数量是否可靠。
- 案例、示范、练习和总结是否真正对应目标，而非仅主题相近；材料是否足够，结论与结果是否有材料和方法支持。
- 学习证据是否对应目标，认知、判断和操作目标不统一套用答题或交作业；未收集到必要表现时不宣布目标达成。
- 跨节是否遗漏必要依赖或无意义重复；独立知识点不强加数量和顺序，真实步骤依赖保留。重要知识可通过不同情境重复加深。

### 教学设计与学习体验

- 从目标学员起点连续看 PPT、讲解、案例与互动：是否讲清怎么做、为什么、何时调整和怎样自检；先提供理解或作答所需的材料，再要求判断。
- 抽象知识是否有具体案例承接，示范是否展示必要过程和完整结果；声称根据选择调整或继续推进时，是否展示可见变化。
- 图呈现关系、变化与对照，讲解补充依据、理由和适用条件；图文是否机械重复、拥挤难读，长材料与多个版本是否堆在一页，必要材料是否离问题太远。
- 解释、示范、练习和总结是否连贯；问题是否突兀，反馈是否接回原教学，按需解释是否提前打断主线；练习后是否主动总结相关知识。
- 不固定每节图数、题数、轮数或结尾，不靠增加必答题或“继续”按钮机械切段。完整示范不因减负被删掉，可调整分段、展开、聚焦及相邻可复制文本。
- 没有实际页面不称视觉检查通过；区分作者预期、代理观察和真人体验。

### 互动与动态教学

先说明互动支持理解、判断、应用、订正还是主动求助；检查是否训练当前知识、收到足够表现、回答是否改变后续帮助。按风险选择代表性情境，不机械穷举每节：

| 学员表现 | 观察重点 |
| --- | --- |
| 正确且充分 | 识别并继续，不重复索答 |
| 错误或部分正确 | 定位问题，提供适当帮助并允许订正 |
| 请求提示或表示不懂 | 给局部线索，不直接代做 |
| 质疑案例或加入无依据判断 | 回应质疑，守住材料与事实边界 |
| 一次表达多个信息 | 完整理解，不只处理一句或重复索取已答部分 |
| 已提供相关信息 | 复用已有信息，不重新访谈，不被旧背景覆盖 |
| 只看示范、暂不练习或主动求助 | 按既定参与方式继续，不强迫无关任务 |
| 达标或准备结束 | 及时收束，不增加门槛或强制结束问答 |

- 需补信息就有真实入口并等待；需订正就允许提交修改稿，按同一标准复查最新完整回答／作品，不能只盯上一处缺口或不断扩张评价标准。
- 检查作答前揭答、输入提示暗藏完整答案、代完成后要求照抄、同义改写误称独立迁移等训练失效。标准与反馈来自目标和材料，不能为模型偏好加码。
- 检查每段必问、达标后追问、无关态度／未来计划／满意度题；认知讲授可以零必答交互，数量不等于学习价值。
- 帮助可变化，必要知识、事实和专业标准不降低；身份、自信和偏好不证明能力。区分帮助下完成、独立完成与迁移。
- 课堂练习可按所选标准反馈；外部实践以解决学员主动提出的困难为主，不强迫提交外部成果验收。教学动作见[方法选择](method-selection.md)，参与边界见[课节设计](lesson-design.md#参与方式与外部实践)，可执行表达见[参与分支](prompt-writing-and-revision.md#参与分支与收束)。

### 内容与运行硬伤

- 内容侧：事实错误、无依据补充、知识遗漏、案例前后矛盾、图文错标、原材料与结果不一致、题目缺材料、示范缺结果、重复内容／选项／索答。
- 证据侧：未知变否定、计划变完成、建议变承诺、模拟变真实执行、虚构经历或成果、声称变化却未展示。读写、保存、自动触发与业务效果分别判断，不把复述或成功提示当成外部执行证据。
- 执行侧：反馈对象错位、需要订正却不能提交、提示词／内部指令／代码外露、空白／报错 PPT、图中伪控件、生成报错、卡住、缺少输入或继续入口、不等待回答、分支错走、不能结束或课节无法完成。
- 明确错误列硬伤；未验证的难懂、负担或节奏问题标为体验风险。运行阻断、事实错误和训练被替代优先于措辞与美观，硬伤多时可单独聚焦排查。
- 区分内容、提示词、资源、平台交互和运行环境原因，不把所有故障归为授课提示词问题。涉及会变的产品能力或专业事实，按需核实当前拥有该事实的来源；无法核实则列未评估，不凭记忆断言。遵循当前官方 Skill，不复制过时语法。

### 跨节衔接与完整路径

- 按本次范围连续学习，检查知识前提、案例对象、任务材料及跨节信息是否正确衔接；旧背景不覆盖当前场景，自有项目不被公共案例替换。
- 关键记忆是否在实际后续路径被正确使用，暂停／恢复是否保持应有状态；不能以变量存在证明记忆有效。
- 从开始到结束是否连贯自然，输入、反馈、继续与收尾是否可用；实际完成状态是否正确，不能以出现重修入口作为完成依据。
- 不把局部路径通过推广为全课通过，不把后台预览通过推广为正式学员入口通过。

## 分批测试、修改与复测

- 按所选问题选择证据：目标、知识和案例匹配可先做源稿审查；实际呈现、等待、反馈、分支、记忆和完成状态需要对应运行证据。运行测试通过真实入口与控件作答、求助、订正并观察后续，不以生成的假想对话代替执行。无法运行时可交付静态发现，并明确哪些运行结论尚不能判断。
- 一批测试聚焦明确问题；可以记录多类发现，但修改按相关原因与影响分批处理，避免一次混改目标、知识、案例、互动和呈现，导致冲突、遗漏或无法判断改动效果。同一原因涉及多个层面时可做必要的连贯修改，说明关联影响；分批不等于强行每次只改一个文件或设置逐批审批。
- 保留修改前对应内容和必要运行证据，依[修改已有内容](prompt-writing-and-revision.md#修改已有内容)落实保留项与关联检查；测试发现不自动变成全课重写。
- 获准修复后，先定点复测原问题，再检查受影响路径；大幅修改涉及目标或内容时重新核对相关目标与内容。局部修改不自动要求全课重测，完整路径检查按本次范围与影响决定。
- 测试模拟资料与通用源稿隔离，不将模拟背景写入正式课程；临时测试改动恢复，不擅自清空真实学习记录。截图与运行记录保留相关上下文。
- 只检查／只给建议时不修改课程或发布。测试不自动授权重写、发布、部署或清空记录；已授权的修复与草稿同步按本次范围和官方 Skill 连续完成，不新增逐项审批。

## 取证、分级与交付

- 每项发现说明课节／位置、本次输入或操作、实际现象、学习影响、判断依据、修改建议和修后验证情况。区分必须修复、可选优化及无法评估，同时保留已正常的路径和未测范围。
- 静态风险写“可能／设计风险”，实际运行写本次输入与观察；不把旧版通过套给新版，无同条件前后对照不将结果归因于单项改动。
- 按实际涉及的事项报告内容检查／修改、平台回读、运行入口与路径、未测范围和待确认问题，以及相关草稿、发布或部署状态；未涉及的操作不要求补做。沿用项目已有记录，正常测试不额外创建进度或回执文件。
- 区分静态审查、设计展示、后台模拟、学员入口试学与真人学习证据。源码正确不证明运行正确，能生成／点通／结束不证明易懂；点击继续、提交成功或一次答对不证明目标达成、掌握或满意。不得用局部通过宣称全课通过，或用代理模拟宣称真人成效。
