# 提示词撰写与修改

教学设计由 [whole-course-design.md](whole-course-design.md)、[lesson-design.md](lesson-design.md) 与 [method-selection.md](method-selection.md) 负责；本文件负责将已选设计表达并一致修改。

## 两类提示词

课程提示词承载全课角色、语气、共同呈现要求和有限个性化边界。授课提示词承载当前节的知识、材料、顺序、具体图示、问题、标准、反馈、分支与结束。课程提示词不替本节临场补造教法或堆各节局部交互；授课提示词对本节关键教学应足够具体。

官方 Skill 的 course-prompt.md、teaching-prompt.md、markdownflow-syntax.md、prompt-semantics.md 负责当前模板、注释、语法和运行契约。只按需读相关部分，不把历史规范写法当作新环境保证；不能用“已写提示词”证明引擎已启用或运行已通过。

## 可执行表达

- 明确知识与事实、教学动作及判断依据，不只写“讲概念／个性化／答错再问”。表达哪些已有信息改变哪种支持，无关或缺失时怎么办。
- 根据实际回答写清评价、下一教学动作、新输入等待、修订后的重查与停止边界。需要选择和理由时使用能收齐它们的实际响应方式；点击继续不代表同意或学习证据。
- 运行时执行作者指令，不将制作流程、编辑记录、变量状态、内部字段或实现解释复述给学员。以常用词自然面向学员讲解。
- 普通讲解保留表达空间；指定原文、术语、材料条件、问题与数字按要求保留。需要原样时采用官方支持形式，但不泛称所有内容有确定性输出保证。
- 明确知识关系与目的，避免无理由写死表格、栏数、标题、卡片、图数及重复总结。作者明确约束保留；取消格式不删除原有知识。
- 必要知识可用新条件、新案例和应用复现，不以重复为由一律删除；问题题干、选项、图示和说明不机械重述。
- 源码结构与注释遵循官方 Skill。关键执行内容不能只放注释或展示代码围栏；新写／明确重写与审查／局部修复区分，不借审核强制规范化全稿。
- 跨节信息有明确消费者、内容、最新决定及缺失回退；首答、修改、提示与教师示范分开。变量或一句“记住”不证明跨节持久化，不用测试学员背景污染通用课程。

## 分类注释与编辑单元

新写或明确重写授课提示词时，使用独立一行的 HTML 源码注释，格式为 `<!-- 类型｜具体用途 -->`。类型便于定位，具体用途说明这一段要展示、解释、判断或支持什么；不只写“PPT一／讲解二”。这是作者编辑标记，不向学员朗读，也不是运行时的分支或版式指令。

按实际内容选择类别，沿授课顺序就地分段，不把同类段落搬到一起：

| 类型 | 用于 |
| --- | --- |
| 教学控制 | 本节范围、已有信息复用、参与模式与执行边界 |
| 材料 | 完整原文、案例、示例文件、处理结果与修改稿 |
| PPT | 图示内容、对照关系、页面布局及其教学目的 |
| 讲解 | 概念、理由、判断、步骤关系和适用边界 |
| 可复制请求 | 交给学员自己助理使用的请求与必要材料 |
| 互动 | 条件提问、实际收答、反馈、订正、求助和分支处理 |
| 收尾 | 当前状态、可带走内容与自然结束 |

例如 `<!-- PPT｜对照原文、实际反馈与改后全文 -->`、`<!-- 互动｜仅补影响帮助的缺口，已有信息直接采用 -->`。类别按需要使用，不要求每节齐全，不规定数量或固定次序；同一类型可多次出现。

- 按有意义、便于独立编辑的教学动作分段，混有 PPT、讲解和请求的长段可在动作边界加注释，不为一句话机械加标签。一个完整案例、结果或复制文本保持完整。
- 题目、实际作答入口及其即时反馈和分支条件作为连贯单元，不能为凑分类把控制与所属问题拆开。注释放在单元前，不插入代码围栏、固定输出块、原样材料或交互控件内部。
- 事实、材料、讲解要求、个性化条件、等待、反馈和停止规则全部留在注释外；忽略注释后，教学指令仍须完整。仅写“互动”注释不会建立真实交互，仅写“PPT”注释也不能替代页面生成要求。
- 已有课程只读审查不自动补注释；局部修复只处理必要范围。作者明确要求“仅整理注释”时，只增改源码注释和必要段落空白，不改正文、顺序、事实、完整示范或交互逻辑，不顺手调整课程提示词、目录或平台设置。
- 仅整理注释时，比较去除源码注释及排版空白后的正文是否逐字同序；代码块、固定输出及交互控件另作精确比对，不能靠忽略空白掩盖缩进或语法变化。按授权同步后独立回读。此类静态等价检查不称作教学路径重测；实际改了分支或执行语义时，再按受影响范围实测。

## 参与分支与收束

[课节设计](lesson-design.md#参与方式与外部实践)统一维护只看、课堂参与、外部实践和主动求助的参与边界。本文件负责把选定分支落实到提示词，而不重复建立另一套参与规则。

- 将当前回答与相关记忆中的意愿、材料、稿件和卡点写成分支条件；缺信息才补问，已有表达优先于泛化的“请选择参与方式”。共同原则放课程提示词，本节进入、回应和结束放授课提示词，清理冲突的旧要求。
- 已有具体卡点就先引用并回应，再接回必要知识和完整示范；已有模拟稿直接采用，不绕开它另编错误，也不推断已做过外部操作。
- 选定订正活动时，写清局部线索、真实新输入等待、完整最新稿复查及结束条件；反馈动作由[方法选择](method-selection.md#单点练习与反馈)维护，不能用标准答案代替学员修改。
- 将剩余必要讲解、示范与新的必答任务区分；达标后接回内容并自然结束，翻页不隐含同意、新作业或成果验收。
- 可复制文件、代码和结构化示例需精确保留时，采用当前官方支持形式并保留完整材料；不能用成功日志或“已生成”替代结果。核对实际可复制文本，不只凭渲染或无障碍树中的空白判断格式。

## 修改已有内容

- 先读取当前版本、来源与必要上下文；平台编辑先按官方同步规则建立基线与版本保护，不用旧本地稿覆盖。
- 区分诊断、局部修复和重写，确定需保留的知识、目标与约束。小范围问题采用最小连贯修复，结构确需重构时说明影响。
- 将修正融入相关位置，合并重复、清理失效约束与编辑痕迹，解决新旧冲突，不只在末尾追加补丁。
- 保留关键解释与判断依据；不能靠删内容掩盖教法问题。源文不足不凭摘要重建原文，不把未知写成否定。
- 检查受影响课程提示词、授课提示词、案例、图示、题目、标准、结束与跨节依赖的一致性。必要修正与可选建议区分，避免扩张标准或提前揭答。
- 按范围同步并独立回读；核对正文及约定保留的课节身份、结构、权限和设置。学习记录清空或外部行动不由修稿暗含授权。

## 验证与交付

普通改稿按当前目标核对受影响内容，不新增测试方向问答；专门测试的方向澄清、证据选择、分批处理、复测及交付由[课程测试方法与要求](course-quality-review.md)统一维护。

- 目标、知识和材料保留检查与教学设计检查分别判断。涉及参与分支、反馈、记忆或结束条件的修改，选择受影响机制的实际路径验证，不机械跑全课或固定分支套餐。
- 仅整理注释时执行上述静态等价检查；涉及完整可复制文件时，必要时比较页面实际文本与源稿。二者不互相替代，也不以源稿一致证明交互或外部系统效果。
- 按本次范围和官方 Skill 同步、回读并报告；说明哪些只是内容完成，哪些有运行证据，不增加无关审批或沿用旧版通过结论。
