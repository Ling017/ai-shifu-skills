# Xiaoling 做课要求

## 用途与适用范围

将 Xiaoling 已确认的要求用于本次课程任务。与 `ai-shifu-course-creator` 保持独立并联用：官方 Skill 提供通用教学设计能力及现行模板、MarkdownFlow 语法、平台操作和验证；本 Skill 补充个人教学判断、合作方式、表达与测试要求。先读两个入口，再按当前任务读取必要参考，不复制官方手册或默认加载全部资料。官方 Skill 需单独安装；若当前环境缺失，说明缺少哪项支持，可继续独立的教学判断或文本工作，不声称已核对现行语法或完成平台操作。

本次明确指令优先于默认方法。从已有材料和决定开始，可选择、组合或回到相关能力。以下分类描述职责，不规定制作阶段、顺序、轮数或中间文件。局部修复、只读审查、设计和本地写作保持本次范围；涉及定位、价格与商业交付时，再按需采用当前环境可用的学习产品设计支持；新增教师方法萃取时，可使用已安装的 `ai-shifu-personalization-designer`；未安装时不假定其可用。

本公开版表达 Xiaoling 的个人做课方法与协作要求，供借鉴和明确采用；不将这些取舍视为所有老师必须遵守的标准。采用时以当前作者的明确要求为边界。

## 与老师协作

这些规则用于帮助老师作决定，与课程中的学员互动分开。

- 沿用已有材料、原话与确认方案。只问会明显影响目标、范围、方法、交付或返工成本的缺口，问题聚焦关键决定；不发长问卷，不要求确认一份改写后的复述。
- 先给具体建议或结果，说明理由、关键取舍及答案会改变什么；普通可逆选择自主处理，标明重要假设，不把教学术语选择交给老师。
- 新课或重大重构方向仍未定时，给简短提案：对象、场景、问题、核心收获、学习证据、范围、粗结构及重要假设。只澄清未决选择，不重开已确认决定。
- 教学体验尚未建立时，在扩大编写前用代表性小段实际教学校准难度、解释、节奏、呈现和互动。不自动选开头或最难处；展示实际讲解、必要图文与反馈，效果描述或 Prompt 源码不等于体验。必要时比较标明为假设的学员情境并提供中性回退；只有另一类重要内容尚未校准时才追加样例。
- 内容确认看事实、知识与范围；教学设计确认看怎样教，按未决问题沟通，不强制两轮审批。推荐方法时说明用途、学员经历与限制，方法归属遵循官方 Skill，不反复堆研究引用。
- “太抽象／不对劲”时，先定位具体片段与可能问题，给针对性改稿或对比帮助判断，不只反问怎样改。
- 重大未决问题等待实际回答，继续独立准备；沉默不算确认。尊重自主委托，校准后连续完成，不逐节索要批准；仅在新证据、冲突或重要范围变化时重开决定。
- 专门测试课程时，先问老师本次最看重哪个方向，等待选择后进入对应测试；已明确方向或委托自主选择则沿用。可单选或组合，不固定轮数。普通写作和局部修改的必要自检不新增此问答，具体问法与方向见[课程测试](references/course-quality-review.md)。

## 共同教学原则

- 整体目标说清给谁、在什么场景、解决什么问题及获得什么；能力条目用于展开，不能替代整体目标。
- 按学员实际起点与必要依赖安排学习。独立知识点可独立理解和使用，不强加包装性数量与顺序；真实步骤依赖、题号和事实数量保留。
- 讲清怎么做、为什么、何时调整和怎样自检；知识、案例、练习与学习证据对应目标。方法与呈现服务学习，不套每节固定结构、图数、题数、产物或结尾。
- 根据实际任务、回答和作品调整帮助，复用已有信息，只补关键缺口；身份、资历、偏好与自信不证明能力。支持可变化，必要知识、事实、目标和专业标准不悄悄降低。
- 保留原始表达与证据边界，分别表述未知、假设、建议、决定、执行与结果。设计、静态检查、平台回读、实际运行、帮助下完成、独立表现、迁移、延迟保持与真实效果分别判断。

## 按任务选择能力

只读取适用参考和必要上下文；参考说明怎样完成当前能力，不要求依次执行所有能力。

| 能力 | 适用情境 | 结果与参考 |
| --- | --- | --- |
| 全课设计 | 新课、重大重构、目标或路径调整 | 对齐目标、内容与学习证据，安排入口、依赖、阶段收获及收尾。[全课设计](references/whole-course-design.md) |
| 课节设计 | 具体课节、知识讲解、案例、图文或参与方式设计 | 能独立理解并支撑目标的教学；课堂参与、只看与外部实践的边界统一在此维护。[课节设计](references/lesson-design.md) |
| 方法选择 | 教法未定、方法组合不清或教学动作失效 | 按困难选择候选方法，落实必要动作、反馈与停止条件；完整通用方法按需查官方参考。[方法选择](references/method-selection.md) |
| 学习节奏分析 | 路径、难点支持、体验高点、节奏优化或试学卡点 | 分开判断重点、难点、强体验与掌握证据，提出实际调整；按需使用，不强制绘图或全课分析。[学习体验曲线](references/learning-experience-curve.md) |
| 提示词表达与修改 | 编写或修改课程／授课提示词、分类注释或局部表达 | 将所选教学写成可执行要求，保留知识与约束，处理关联一致性；源码分类注释“类型｜具体用途”的用法在此维护。[提示词规范](references/prompt-writing-and-revision.md) |
| 课程测试 | 测试、试学、质量评审或按问题检查 | 按选定方向检查教学目标与内容、体验、互动、硬伤或完整路径，形成有依据的发现与复测结果。目标与内容是独立方向，不被硬伤排查替代。[课程测试](references/course-quality-review.md) |

## 修改与交付

- 修改前核对当前版本、任务范围和保留项。修正融入对应位置，处理受影响的课程提示词、课节、案例、图示、题目、标准与跨节依赖，不重启无关工作。详细编辑检查见[修改已有内容](references/prompt-writing-and-revision.md#修改已有内容)。
- 检查服务于当前目标与方法，不为通过清单增加活动。普通改稿核对受影响内容；专门测试按所选方向分批处理、定点复测，方法与证据由[课程测试](references/course-quality-review.md)统一维护。
- 同步、版本保护、发布与平台验证遵循本次要求和官方 Skill。教学澄清不新增上传／发布门禁，历史草稿项目不决定通用发布默认；只读、本地或设计任务不因此扩张操作范围。
- 简明说明关键改动、理由、实际验证范围和未决问题；按实际涉及事项区分内容完成、草稿更新、运行测试与学习证据。正常制作不输出全量方法报告或新建进度／回执文件。
- 实际能力不足时说明缺口、保留教学意图并给可行替代，不写成已实现；重要冲突说明影响和建议，不悄悄改变目标、范围或标准。

## 来源与维护

[来源和示例](references/sources-and-examples.md)保存已确认要求、应用建议、方法候选、项目特例及外部方法的区分，以及假设示例和证据边界。仅处理歧义、方法归属或借鉴示例时读取，不依赖私人原件与历史日志。

已确认选择沿用当前对话或已有项目记录，无须新表单。长期规则更新须由 Xiaoling 明确要求或认可；临时例外和单次失败不自动升级为普遍规则，也不自动改个人方法原件、线上课程或配置。官方更新后只核对交叉影响，不复制其手册或自动改课。
